Installed it.
Now what?

By Kowshik Kesavarapu 6 min read Oct 13, 2026

01Install it

Claude Code runs in your terminal, on Windows, macOS and Linux. The recommended route is the native installer. Open a terminal and run the line for your system:

>_PowerShell
—☐✕
# Windows
PS C:\> irm https://claude.ai/install.ps1 | iex

# macOS / Linux / WSL
$ curl -fsSL https://claude.ai/install.sh | bash

Prefer a package manager? Windows has winget install Anthropic.ClaudeCode and macOS has Homebrew. There is also an npm package (npm install -g @anthropic-ai/claude-code) if you already live in Node. Whichever you pick, close and reopen your terminal afterwards so the claude command is found.

Check it worked:

>_PowerShell
—☐✕
PS C:\dev> claude --version
PS C:\dev> claude doctor   # checks your install and setup

If something fails: claude: command not found almost always means the terminal was open before the install, or the install folder isn't on your PATH. Reopen the terminal first. On Windows, if it complains about Git, install Git for Windows and try again. claude doctor tells you what it found.

02Sign in once

Go to a project folder and type claude. The first run opens your browser to sign in. You need a Claude subscription (Pro or Max) or an Anthropic Console account with API credits. After that it remembers you.

It will also ask whether you trust the folder. That prompt is a real safety check, not a formality: Claude Code can read files there and, with your approval, edit them and run commands. Only say yes to folders you actually own or trust.

03Your first session: look before you touch

The best first prompt changes nothing. Ask it to read:

>_PowerShell
—☐✕
PS C:\dev\shop> claude

> explain how this project is laid out and how to run it

It will open files, follow imports and answer from what it finds. This is the fastest way to learn an unfamiliar codebase, and it is also a test: if the answer is wrong, you've learned what to put in your CLAUDE.md from Day 2.

Then make one small real change, with a clear ask:

>_PowerShell
—☐✕
> add a /health route to src/server.ts that returns { ok: true }.
  Follow the style of the other routes, then run the tests.

Notice what happens. Claude proposes each edit and each command, and waits for you. You can approve one at a time, or say no and explain why. Nothing is saved until you allow it.

04What you'll see while it works

01Permission prompts

Before editing a file or running a command it asks. Read what it is about to do. This is you staying in control (we'll go deeper on permissions later in the series).

02Diffs

Edits appear as a before and after. Check them like you'd check a teammate's pull request.

03Esc to stop

Heading the wrong way? Press Esc to interrupt, then redirect. Two Esc presses let you step back to an earlier message.

05Leaving and coming back

Type /exit (or press Ctrl+C twice) to quit. Your conversation is saved, so you can pick up where you stopped:

>_PowerShell
—☐✕
PS C:\dev\shop> claude --continue   # resume the last session in this folder
PS C:\dev\shop> claude --resume     # choose from earlier sessions

Safety net: run your first sessions inside a git repository. If a change isn't what you wanted, git diff shows it and git restore . throws it away. Trying things is cheap when undo is one command.

06Try this today

InstallRun the installer, then claude doctor.
ReadAsk it to explain a project you know. Check its answer.
ChangeOne small edit, with a file and a "done".
ReviewRead the diff. Keep it or git restore ..
