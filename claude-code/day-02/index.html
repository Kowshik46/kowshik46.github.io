01Why context is everything

A new Claude Code session does not automatically carry over your previous conversation. It can read your files, but unless something tells it, it doesn't know your preferences, your team's rules or the command you use to run the tests. Continuity comes from what is written down: CLAUDE.md (and auto memory, if you have it on) is loaded at the start of every session. When it doesn't know, it guesses, and a confident guess in the wrong framework or style costs you a round of fixes.

Two habits remove most of the guessing: a CLAUDE.md file for what is always true about your project, and clear asks for what is true about this one task.

02CLAUDE.md: a briefing it reads every session

CLAUDE.md is a plain Markdown file in your project's root folder. Claude Code loads it at the start of every session, so you write the briefing once instead of repeating it. You can also keep a personal one at ~/.claude/CLAUDE.md for preferences that apply to all your projects.

The quickest start is to let Claude draft it. In a project folder, run:

>_PowerShell
—☐✕
PS C:\dev\my-project> claude

# inside Claude Code
> /init

It reads your project and writes a first CLAUDE.md. Then edit it. The draft is a starting point, and you know things it can't see.

03What belongs in it

Keep it short. A long file is a file that gets ignored, and every line uses up context. Include only what Claude can't work out by reading the code:

01Commands

How to install, run, test and lint. This is the single most useful section, because it lets Claude verify its own work.

02Conventions

The rules a new teammate would be told on day one: naming, where new files go, which library to use for what.

03Things to avoid

The mistakes you keep correcting. "Don't edit generated files." "Never commit directly to main."

A small example you can copy and adapt:

>_CLAUDE.md
—☐✕
# My Project
A web app for tracking orders (React + Node).

## Commands
- Install: pnpm install
- Test: pnpm test (run before finishing any task)
- Lint: pnpm lint

## Conventions
- TypeScript only, no new JavaScript files
- UI components live in src/ui; follow existing patterns
- API calls go through src/api/client.ts

## Avoid
- Don't edit anything in dist/ (generated)
- Don't add dependencies without asking

Rule of thumb: if Claude gets something wrong twice, add a line to CLAUDE.md. Treat it as a living file that grows from real mistakes, not a document you write once and forget.

04Clear asks: the other half

CLAUDE.md covers what's always true. Each request still needs to say what you want now. A good ask has three parts: where to look, what "done" means, and any constraint.

Vague"Make the search faster."
Clear"Search on the orders page takes 3 seconds. The query is in src/api/orders.ts. Find why it's slow and fix it without changing the response format. Run pnpm test when you're done."

You don't need long prompts. You need the right three sentences. Naming a file also saves Claude from searching the whole project, which keeps the session faster and focused.

05Copy-paste checkpoint: three starter files

Pick the one closest to your project, paste it into a file named CLAUDE.md in the project root, then change every command to match what you really run. The point of each file is the same: tell Claude the exact build, test and lint commands so it never has to guess, and say what to avoid. Replace anything in [brackets].

Next.js / React frontend

>_CLAUDE.md (Next.js / React)
—☐✕
# [App name]
Next.js (App Router) + React + TypeScript web app.

## Commands
- Install: pnpm install
- Dev server: pnpm dev (http://localhost:3000)
- Type check: pnpm tsc --noEmit
- Lint: pnpm lint
- Test: pnpm test (run before finishing any task)
- Build: pnpm build (run before opening a PR)

## Conventions
- TypeScript only, strict mode. No any without a comment saying why.
- Server Components by default; add "use client" only when needed.
- Shared UI lives in src/components; data fetching in src/lib/api.
- Style with [Tailwind / CSS Modules]; do not add another styling library.

## Avoid
- Don't edit .next/ or anything generated.
- Don't add dependencies without asking.
- Never commit .env* files.

Python / FastAPI backend

>_CLAUDE.md (Python / FastAPI)
—☐✕
# [Service name]
FastAPI service with PostgreSQL. Python 3.12.

## Commands
- Setup: python -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
- Run: uvicorn app.main:app --reload
- Test: pytest -q (run before finishing any task)
- Lint and format: ruff check . && ruff format .
- Types: mypy app

## Conventions
- Routes in app/routers, business logic in app/services, never in the route.
- Request and response bodies are Pydantic models. Type hints everywhere.
- Database changes go through Alembic migrations: alembic revision --autogenerate -m "..."
- Every new endpoint gets a test in tests/.

## Avoid
- Don't edit applied migrations; add a new one.
- Don't call the live database from tests; use the test fixtures.
- Never log secrets or tokens.

Generic scripts repository

>_CLAUDE.md (scripts repo)
—☐✕
# [Repo name]
A collection of small standalone scripts ([Python / Bash / Node]).

## Commands
- Run a script: [python scripts/name.py --help]
- Check syntax: [shellcheck scripts/*.sh] or [python -m py_compile scripts/*.py]
- Tests (if any): [command]

## Conventions
- One script, one job. Each has a usage comment at the top and a --help.
- Read config from environment variables; never hard-code paths or secrets.
- Print a clear error and exit non-zero on failure.
- Scripts must be safe to run twice.

## Avoid
- Don't delete or overwrite files without a --force flag.
- Don't add dependencies for something the standard library can do.

Not sure what to put in your own? Start with the Commands section. If Claude can build, test and lint your project without asking you how, the file is already doing its main job. Add the rest as it makes mistakes.
